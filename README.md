## How it works

Content lives in `config/*.yml` and is rendered through Jinja2 templates (`src/jinja/`) into a single `index.html`:

```
config/*.yml  -->  main.py (Portfolio class)  -->  Jinja2 (src/jinja/)  -->  index.html
```

```
config
|-- assets/            # images, icons, CV
|-- profile.yml         # name, role, contact info, social links
|-- about.yml           # bio, "what I'm doing", soft skills, core technologies
|-- experience.yml      # work experience & education
|-- skills.yml          # technical skills
|-- projects.yml        # portfolio projects
|-- blog.yml            # blog posts (auto-generated by blog.py, do not edit by hand)
|-- contact.yml         # contact form + map embed
|-- navbar.yml          # navigation labels
```

> [!TIP]
> Icons use the [Ionicons][ionicons] set — reference them by name, e.g. `icon: "logo-linkedin"`.

## Local development

```bash
# Install dependencies (Poetry, virtualenv created in-project)
poetry install --with=dev

# Build the portfolio (renders index.html from config + templates)
poetry run python main.py

# Sync blog posts from remote source (updates config/blog.yml)
poetry run python blog.py

# Lint
poetry run ruff check .

# Run tests
poetry run pytest
```

## CI/CD

- **deploy.yml**: runs on push to `master` — lints with ruff, builds with `main.py`, deploys to GitHub Pages.
